# Agentception

[![CI](https://github.com/arun3676/agentception/actions/workflows/ci.yml/badge.svg)](https://github.com/arun3676/agentception/actions/workflows/ci.yml)

Agentception is an evidence-oriented job discovery application. The intended
product flow is:

> anonymous role/location search -> sign in before personal data ->
> source-backed fit and research -> truthful tailoring -> application outcomes ->
> targeted learning

## Current release posture

The public deployment is in a containment phase while private account ownership,
durable workflow state, and the production tailoring API are rebuilt.

Available now:

- Anonymous role and location search.
- Live workflow status and job results.
- Public study resources.

Deliberately unavailable until their security and data contracts are complete:

- Resume upload and personalized fit analysis.
- Resume tailoring and document export.
- Saved applications, personal learning history, and other account data.
- Outreach, readiness percentiles, trust profiles, portfolios, cohorts, and other
  experimental proof/benchmark surfaces.

An unavailable feature must say that it is unavailable. It must not show demo
progress, invented scores, placeholder user history, or developer setup
instructions.

## Evidence rules

Every user-visible claim follows one of three forms:

1. Source-backed, with the source and observation date.
2. Clearly labelled as an estimate, including the method and limitations.
3. Unavailable, with a concise explanation.

The current matching and parsing evaluations are useful engineering signals, not
population-level proof. The historical resume dataset represented one person and
is being replaced by a fully synthetic fixture. Do not describe existing scores
as a probability of being hired, an ATS verdict, a percentile, or verification.

## Local development

Python 3.11.15 and Node.js 22+ match CI and production configuration.

```powershell
Set-Location agentception
python -m pip install uv==0.11.28
uv lock --check
uv sync --locked --group dev
Copy-Item .env.example .env
uv run uvicorn server.app:app --reload --port 8000
```

In a second terminal:

```powershell
Set-Location agentception\ui
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Never commit `.env` files. The containment browser receives only
`VITE_BACKEND_URL`. Supabase browser configuration returns in the later account
foundation change; provider and Supabase secret keys are always server-only.

## Validation

From `agentception/`:

```powershell
uv run --locked python -m compileall server
uv run --locked python -m pytest -q --strict-markers
uv run --locked python -m pytest evals -m eval -q --strict-markers
uv run --locked python scripts/check_repository_privacy.py
```

Frontend checks:

```powershell
npm --prefix ui ci
npm --prefix ui test
npm --prefix ui exec tsc -- -b
npm --prefix ui run lint
npm --prefix ui run build
npm --prefix ui run check:bundle
npm --prefix ui audit --omit=dev --audit-level=moderate
```

The CI privacy job rejects tracked browser artifacts, databases, non-synthetic
resume goldens, and committed secrets. E2E fixtures must use the canonical
synthetic identity generated by:

```powershell
uv run --locked python scripts/build_synthetic_resume_fixture.py --goldens
uv run --locked python scripts/build_synthetic_resume_fixture.py --output tmp/pdfs/synthetic-resume.pdf
```

The generated PDF is a temporary test input and must not be committed.

## Deployment

- Vercel hosts the Vite UI.
- Railway hosts FastAPI.
- Supabase is the reviewed target for authentication, Postgres, and private
  document storage; the containment release does not pretend that migration is complete.
- Production deployment is manual and follows reviewed pull requests.

Do not run migrations through the transaction pooler. Inspect the actual
Agentception Supabase project, dry-run migrations against a disposable copy, and
use a direct or session-mode migration connection. The connected Cork Supabase
project is unrelated and must never be used for Agentception work.

See [deployment guidance](docs/DEPLOYMENT.md) and the
[privacy history rewrite runbook](docs/PRIVACY_HISTORY_REWRITE.md).

## Known architectural work

The containment release does not pretend the later architecture already exists.
Remaining work includes consolidating SQLite and conflicting SQL paths into one
versioned Supabase/Postgres schema, moving process-local jobs/events to durable
workers, rebuilding authenticated resume/tailoring APIs, and adding a complete
synthetic staging and production acceptance pass.
